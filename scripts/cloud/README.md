# 连接云端开发数据库（占位）

本文件是一份**占位说明**，描述「在本地跑 charon，连云上开发库」的**预期做法**。目前没有配套脚本，也没有经过验证的实际接入——写在这里只是为了先把约定固定下来，避免每个人各接各的。

## 为什么需要它

charon 启动时会真连 `DB.DataSource`，连不上就直接退出（不做内存回退，见 `internal/config/config.go` 与 `internal/svc/servicecontext.go`）。本地开发若想用一份真实数据，就需要一个稳定的方式连到云上开发库，而不是每次改配置。

## 预期做法：经跳板机开 SSH 隧道

云上数据库通常只允许从跳板机（bastion / jump host）访问，不对公网开放。预期流程：

1. 建立到跳板机的 SSH 隧道，把云库端口转发到本机端口：

   ```bash
   ssh -N -L 15432:<云库内网地址>:5432 <user>@<跳板机地址>
   ```

   - `-N`：只做端口转发，不开交互 shell。
   - 本地端口建议用非默认的 `15432`（或别的空闲端口），避免和本机已有的 Postgres（5432）抢端口。
   - `<云库内网地址>:5432` 是**跳板机视角**能访问到的数据库地址，不是公网地址。

2. 让 `DB_DATA_SOURCE` 指向**隧道的本地端点**，即本机回环：

   ```bash
   export DB_DATA_SOURCE="postgres://<user>:<pass>@127.0.0.1:15432/<db>?sslmode=require"
   ```

   `127.0.0.1:15432` 就是上面 SSH 隧道在本机暴露的入口。

   > `sslmode` 按云库实际要求填。云上托管 Postgres 一般要求加密连接，本地隧道本身不替代云侧的 TLS 要求。

3. 正常按 `scripts/dev-up.ps1` 或 `scripts/dev-up.sh` 启动即可；脚本会用这个 DSN 跑迁移、连数据库。

## 不要做的事

- **不要把 `DB_DATA_SOURCE` 直接指向云库的公网 DSN**，从笔记本直连。原因：多数云库本来就没开公网；即使开了，等于把数据库端口暴露给整个互联网、并绕过跳板机的访问控制与审计。隧道要的就是「流量只从跳板机出」这一点。
- 不要把云端密码写进 `etc/*.yaml` 或提交进仓库。密码只放本机环境变量 / `.env`（`.env` 已在 `.gitignore` 里）。
- 不要在云开发库上跑**破坏性迁移试验**。要试 schema 改动，先在本地容器库上验证。
