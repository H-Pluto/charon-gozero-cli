# 云资源对接清单

**本文件是待填写清单。** charon 目前的部署目标环境尚未确定，下面列出接入云环境时需要交接/确认的资源。填完这份清单，接手的人就能独立部署。

> 现状说明：当前脚手架只在本地用 `docker compose` 验证过（且本项目环境无法访问镜像仓库，Postgres 相关的端到端验证**未在本机跑通**，见 [README 验证说明](../README.md)）。云上一切均未部署。

## 7. 上生产前的必查项

按重要性排序：

1. **`Auth.Mode` 绝对不能保持 `require` 且暴露公网。** 它不是真鉴权，任何 `Bearer <任意字符串>` 都能通过。要么等 `sdk-auth` 合入切 `sdk`，要么保持 ClusterIP。
2. **`Mode` 改成 `pro`**（`etc/charon-api.yaml` 与 `etc/charon-rpc.yaml`）。`dev` 会关掉自适应限流，且 rpc 会开 gRPC 反射暴露方法签名。
3. **`DB.MaxOpenConns` 与副本数算过账**。默认 20 × N 副本不能超过数据库上限。
4. **`Log.Encoding` 改成 `json`**，否则日志系统难以结构化采集。
5. **删掉 demo_item**：表、`api/desc/demo.api`、`internal/handler/demo/`、`internal/logic/demo/`、`internal/repo/demo_item.go`、`internal/model/demo_item.go`、`internal/types/demo.go`，以及 `routes.go` 里对应的路由。见 [demo.api 顶部清单](../api/desc/demo.api)。
6. **`Telemetry.Disabled` 按是否有 OTLP collector 决定**，开着但连不上会刷错误日志。
7. **`Health.RequireToken` 按探针是否暴露到不可信网络决定**。
